# Cloud Functions

Part of the repo conventions split out of `CLAUDE.md` (see its "Read before you touch" table). Rules here bind exactly as if they were in `CLAUDE.md`; a reference like `CLAUDE.md "X"` in older text means the bullet titled X, now in whichever conventions file holds it.

- **A function that parses a person's link reads it in one linear pass.** Never a lazy `[\s\S]*?` or an unbounded `[^>]*` over a page: a hostile 1.5 MB body turns those quadratic and blocks the instance for minutes (the 6 s timeout only aborts the fetch). `fetchPageContent`'s `readPage` is the reference, and the public-address check allows only global-unicast IPv6. Any input cap is benchmarked raised too (see Validation).
- **A callable that deletes a parent document ends with `recursiveDelete` of its ref, after any Storage cleanup,** so subcollections added later (inquiries, invites) go with it and a rerun finishes an interrupted run (`deleteSale`, `deleteTrip`); never hand-delete the known children and then the parent. Its client's `httpsCallable` timeout matches the function's (`{ timeout: 540_000 }` for 540 s; the default 70 s reports `deadline-exceeded` while the delete is still running), counts `not-found` as already deleted, and reads `deadline-exceeded` as "still deleting". It validates the id's shape and logs it.
- **A device turns a callable's refusal into its own copy, never the server's `message`.** It reads the error's `code`, and where one code has several causes the server adds a `details.reason` the device checks; a server message can name the app or speak to a developer, and copy checks never see it (Helm: "That person was removed" vs a key that won't open, both `failed-precondition`).
- **A handler that dispatches on a client-supplied key checks `Object.hasOwn` (or uses a `Map`),** never a bare object lookup that resolves names like `toString`.
- **A callable that makes several outside writes in one request can be retried safely.** It runs them in parallel with a per-call timeout that fits well inside the function's own, marks each write with a key derived from its content and a per-send key the client makes once and reuses only when retrying an unknown outcome, and skips one already made (the dashboard's answer comment carries `<!-- pipeline-answer:<hash> -->`; a hash of the content alone swallowed the same answer sent again later and reported it as sent), treats any 2xx as done even when the body can't be read, and logs only an error's name. Its client reads a thrown error as "unknown", never as "nothing was sent", and it sends a few writes at a time and reads 429, or a 403 with a retry hint, as "busy, try again", never as a bad token. A write that follows another (issues opened after a comment) carries its own marker and is looked for on every path, the retry that finds the first write included, and deduped within the request too (the list of what exists is read once), so a crash between them is healed, never reported as done; GitHub content writes (issues, comments) go one at a time, since its secondary rate limit refuses concurrent ones. An emulator rehearsal reports exactly what production would do for that input (no issues for an open PR), or says it can't.
- **A best-effort side read never decides a link's status, except for the code that proves it dead; a cached figure is dated by its source.** A balance or logo read inside a sync, or a context read that falls back to empty, logs its failure and goes on (a capped query orders before it limits, so the cap drops the oldest), since the main call proves whether the credential works; it rethrows only a provider code that means the link can't work at all (Plaid's NO_ACCOUNTS). A provider's cached figure carries the provider's own time, else the connection's last refresh (`/item/get`), never the time of the read, when a consumer treats "dated today" as fresh (Runway's moves count bills only from the balance's day).
- **Third-party results are cached carefully.** Never cache an empty or null answer for the full TTL (a parsing gap would stick for weeks), round any privacy-reduced input (coordinates) on the server before the upstream call so a shared entry never depends on who populated it, and list every contract detail taken from docs alone (date formats, parameter names, paging) in the PR body as unverified: a fake server you wrote yourself doesn't verify it.
- **A strict tool schema has no length keywords.** A tool sent with `strict: true` (a model's terminal tool) never carries `maxLength`, `minLength`, `maxItems` or `minItems`, which strict mode refuses with a 400 on every call; the limit goes in the description, and the server enforces any limit it needs. A wrapper that stops an aborted run before its next step reports the outcome as aborted, never as the inner step's own ending, so a restart loop that reads only the ending doesn't take a hand-over or a limit as the answer.
- A third-party key that can't be domain-restricted is a Functions secret behind an `onCall` (never in the browser, a response or a log); a free-tier API shared by all users gets a server-side cache and a daily budget guard. Full rule in `docs/conventions/data-contracts.md`.
- **A scheduled sender never flushes a backlog.** Anything that sends on a timer drops what is long overdue (reminders: 30 minutes, then `expired`, a yearly one rolls forward) instead of sending it late, because an outage or a missing index would otherwise deliver every missed message at once the moment it is fixed.
- **`functions/README.md` is the functions reference — keep it current in the same PR.** Adding, renaming or removing a function updates its row in the Functions table (trigger, app, purpose). A new secret or env var gets a "Secrets and config" row, and a function that caches, budgets or fetches for a user gets a per-function note. A new secret is created in production before the PR merges (CI deploys every function on merge, and a missing secret fails the whole deploy), and the PR body says so.
- **A function that fetches a person's link uses the guarded fetch.** `functions/src/linkMetadata/safeFetch.ts` (public-address check, redirect cap, byte cap, timeout) is the one way a function opens a user-supplied URL, as `fetchLinkMetadata` and `fetchPageContent` do; never a bare `fetch` of a typed link.
- **A page-reading function returns what the caller asks for.** `fetchPageContent` takes `include` (`text`, `structuredData`, `meta`, `headings`, `images`), optional `schemaTypes` and a text cap, returns only those kinds, and knows nothing about what the app does with them; a new kind is a new extractor in that file, never a flag for one app. The app's own `lib/` turns the content into its entity (Pinch hands the page text and any Recipe data to the AI reader, which reads partial or odd pages a hand-written parser misses). Image addresses it returns are third-party: load them through `FallbackImage`. A parser of a person's link caps every collection it builds (images, headings, nodes) before any step that is quadratic in its size, and starts every sticky pattern on a token, never on `\s*`; benchmark it against a 1.5 MB body of 100,000 `<img>` tags and of 780 `<meta>` tags padded with 1,900 spaces each.
- **Local setup lives in scripts, not memory.** A step every developer must repeat (like building `functions/lib/` before the emulators load it, handled by the `preemulators*` hooks) becomes a `package.json` script or `pre*` hook, and the README documents the command rather than the manual step.
- **A new `onCall` function needs nothing run by hand to reach the browser.** The organization policy refuses the CLI's public IAM grant, so `fb:deploy:smart` (what the merge workflow runs; `fb:functions` and `fb:deploy` skip this) sees `Unable to set the invoker`, opens every callable with `npm run fb:invoker -- --all` (`--no-invoker-iam-check`) and deploys once more. A callable that skipped that path (symptom: browser CORS error; Cloud Run request logs show a 403 on the `OPTIONS` preflight) is fixed with `npm run fb:invoker -- <function>`; it refuses a function that is not an `onCall`, whose IAM check must stay on, except an HTTPS webhook in its `PUBLIC_WEBHOOKS` list (a provider calls it with no Google identity), which is opened with the callables and must verify the provider's signature itself and answer 401 to anything else. Because a callable is then open to anyone with its address, it checks `request.auth` itself unless it exists for signed-out visitors, and `functions/README.md` says which. See README's [invoker section](README.md#new-cloud-functions--cloud-run-invoker-access). A callable that opens sealed data sets `enforceAppCheck: true` (every Helm callable that does, `writeHelmTopic` included). A client-writable list of ids is capped server side before any per-id read or write.
- **Every push nobody asked for goes through `sendBudgetedPush` (`functions/src/notifications/`), never `sendPushToUsers` directly.** It drops the push overnight (22:00-08:00 in the zone passed) and past 3 a day, per person per app, counting in `apps/{appId}/pushBudget/{uid}` (Admin SDK only; no rule matches it, so clients are denied) inside a transaction before the send. Only a reminder the person set themselves (`sendScheduledReminders`, a timer) calls `sendPushToUsers` straight. A function that sends several kinds on one morning builds one push per person, not one per kind. The helper and its params carry no app's words (`appId` is the only app input); the rule is `product.md` "A push nobody asked for".
- **A push that is a person waiting on someone goes through `queueBundledPush` (`functions/src/notifications/bundledPush.ts`), never `sendBudgetedPush`, because it must not be dropped.** State is `pushBundles/{appId}_{uid}` (Admin SDK only, no rule): the first goes at once, others within 15 minutes go as one from `sendDueBundledPushes`, and anything in quiet hours (22:00-08:00 in the zone passed, UTC when unknown) goes as one at the next 08:00 (`notifications/zonedTime.ts`). The app registers `confirmItems` (what still matters at send time) and `summarize` (the words) in `BUNDLE_HOOKS`; the decisions are pure and checked with a fake clock. Nothing is dropped on a failed send: the items stay in the doc until the send is acknowledged (a claim takes a lease and leaves them in place, an expired lease is claimed again, a failed immediate send is queued back), a retry has an attempt cap (5, then it is given up with counts logged) and passes the quiet-hours gate like any send, and a send where every device still good failed counts as a failure (dead tokens are removed and are not one; zero devices is a success). The payload names the thing, never the person asking.
- **A once-a-day sender claims its day in a transaction before it sends,** so a send never doubles a day, and its window is shorter than its cadence; a feature that pushes at a time the person chose polls no slower than the shortest thing it times, sends through `sendPushReport` (the budget's quiet hours would drop a chosen hour after the day is claimed) and deletes its claim when the send throws or every device fails, so the next run tries again, checks an existing claim before its counts, opens a sealed setting only after its cheap checks and in bounded batches, and re-reads a queued reminder after waiting. A new Admin-SDK query ships its index in the same PR (`check:indexes` reads a trailing `.limit()`).
- **An optional provider credential is read at run time and its absence means the provider is skipped,** because a bound secret or a `defineString` makes the whole deploy need it. A provider list has one switch (`IMAGE_SEARCH_PROVIDERS`), a free-tier quota is counted in the provider's own time zone and stopped short of the limit, results from a third party are copied by name, https only, and a picture the person picks is loaded once at the tap so an unreachable one is refused there, not after saving. A script that checks a credential checks the same kind the code will use (application default credentials are `gcloud auth application-default print-access-token`, not the gcloud account's).
- **"Am I in the emulator?" is `isRunningInEmulator` (`functions/src/emulator.ts`), never a platform variable.** The Functions emulator sets `K_SERVICE` and `K_REVISION` like Cloud Run does, so `FUNCTIONS_EMULATOR === 'true' && !K_SERVICE` is false inside the emulator and sent `getFirebaseUsage` to real Cloud Monitoring (a 400 locally). The Emulator Suite's hub (`FIREBASE_EMULATOR_HUB`) is the one variable a deployed function never has. A guard that decides emulator versus production is run in the emulator and against a production-shaped environment before it ships.
- **A file `functions/` copies from `src` sits in `functions/src/vendor/` (one app's file in that app's folder under `functions/src/apps/`), headed as a copy, and `check:server-copies` keeps it identical.** The keyring helpers are `functions/src/appKeys/` (an app's key file holds its paths, key-id prefix and canary text; the keyring loader, the canary check and its scheduled run are generic), and a callable that needs a recent sign-in uses `functions/src/auth/recentSignIn.ts`.
- **A model call from a Function goes through `functions/src/ai/` by role.** A model id appears only in `models.ts`, and no file there names an app. The provider is Anthropic's API through `functions/src/ai/providers/anthropic.ts`, with `ANTHROPIC_API_KEY` set by `npm run ai:anthropic-secret` (which checks the key); a tool loop runs over an in-process MCP server built per call with the caller's uid in its closure, and no tool takes a uid, an id or a token. A paid loop records spend after every turn, not at the end, keeps its worst case (turns × a per-turn timeout, with the SDK's own retries off) inside the function's timeout so a killed call leaves nothing uncounted (a second run or retry inside one call gets the time left in the call, never a fresh full loop limit, and is skipped when too little remains), and takes its rate and budget reservation right before the first paid call, after every check that could skip it. Which provider errors give a try back is decided on the SDK's error classes, tested with real instances, never on code strings (connection and abort errors are status-less subclasses of the API error). A device's table of a Function's failure codes is copied from the literals the server emits, with a check case per literal, never written from what the codes ought to be (a table that waited on a code the server never sends left every such failure on the default reason), and a sentence is written only for codes that can reach the state it describes (a code that gives the attempt back never reaches "failed"). A callable that records a failure on the document and still answers normally returns the status it left, and the device reads it: a call that returned is not a call that worked. A span the model is told to quote exactly is checked as words on word boundaries (normalised, punctuation folded), never as a raw substring: models add a full stop or curl a quote mark. A limit a call is refused for reaches the caller with its real reset (a 10-minute window is never worded as tomorrow), and a reservation taken before the call is given back on every path where no paid call ran.
- **Speech to text and text to speech go through `functions/src/voice/` and `src/lib/speech/voice/`.** They are provider-independent adapters with a site-level allowance and budget separate from the AI budget, and keys stay on the server (streaming listening by a short-lived token, speaking through `streamSpeech`); an app supplies its id, limits and voice identity in `VOICE_APPS`, never its own provider call. A listening adapter whose `start` awaits (a microphone prompt, a token) keeps a Stop or Cancel asked for during the await and honours it when the await ends; Cancel never sends buffered speech to the provider; and a client that drops a reservation the server made (a token that arrived too late, a listen cancelled first) reports it back at zero, so an overdue charge never bills work nobody used. A transcription reserves the worst case the server derives (the length cap), never a length the client wrote; when that worst case doesn't fit what is left but the clamped claimed length does, it reserves the clamped length, so a short note is never refused as used up, and settles at the measured length (the emulator path settles at the clamped length, never the cap). A cloud reading hands its line to the device voice only before its first sound (slow, held, refused or undecodable), never part-way through, and reports the id of whichever voice actually spoke (a check asserts it on both paths); a streamed HTTP answer sends its status and headers only after the provider's first byte, so a provider that ends or fails before any audio still answers 502 with the reservation given back, and it lists a header the page reads in `Access-Control-Expose-Headers`; an HTTP function that checks its origin does it in the handler too, since CORS only stops a browser reading the answer.
