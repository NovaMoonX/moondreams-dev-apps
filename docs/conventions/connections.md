# Connections

Part of the repo conventions (see `CLAUDE.md` "Read before you touch"). These files are the source of truth; nothing else keeps a copy.

How one app reads another app's data, or a connected Google service, so every app follows one process and an app can later move to its own domain or project without its readers changing. Read it before touching anything under `src/lib/connections/`, `functions/src/connections/`, an app's `share/` folder, or code that wants data another app owns.

- **An app reads another app only through that app's published read contract.** Never a Firestore path, a slice or a type from another app's folder (`check:connection-boundaries`). Each source app owns `src/apps/<app>/share/manifest.ts` (its categories: id, the person's words, kind, On or Off, and its Never lines) and `functions/src/apps/<app>/share/adapter.ts` (maps its records to the shared kinds, returns only what that uid can already see in the app, never another member's private items, contacts or messages), registered in `SOURCE_ADAPTERS`; an app that shares nothing declares `shares: []`. A category added later is Off. A reader owns a sink (`READER_SINKS`) that seals copies into its own tree with their source, account, freshness and `transformVersion`. Grants live at `connections/{uid}/grants`, are read by their owner from any app and are written only by the platform's callables. Tokens are sealed under `CONNECTIONS_MASTER_KEYS` in `connectionsServer/`, used only inside `functions/src/connections/`. Everything is read only until an app ships its own write permission. An app that moves to its own domain or project keeps its contract: the platform's `SourceClient` switches from in process to `/connections/v1` over HTTP with a grant-scoped service token, and nothing in the reader changes. `check:adapters` proves each adapter against owner, member and non-member fixtures.
- **The pieces are shared and named, so a reader or a source joins without new platform code.** The contract is `src/lib/connections/contract.ts` (import-free; `npm run connections:vendor` writes its server copy and each app's server manifest, and `check:server-copies` fails when one is stale, so edit the `src/` file and re-run it). A reader lists its grants with `useConnections({ readerAppId })`, draws them with `ConnectedSourcesList` (rows the caller words) and changes them only through `connectionCalls` (`grantConnection`, `updateConnection`, `endConnection`, each a transaction that re-reads the grant and checks both apps with the site's `canOpenApp`). A source app registers its manifest in `src/lib/connections/sources.ts` and its adapter in `SOURCE_ADAPTERS`; a reader adds its grant page to `READER_APPS` on both sides. An adapter reads only under the uid's own paths, sends every record through one function that writes exactly `SHARED_RECORD_KEYS`, and reuses the app's own thresholds (a "use soon" window is the app's, never a new number). `check:connection-boundaries` greps the shared files for every app's words; a hit that must stay (a `SharedKind` named `trip`, a registry key) goes in its allowlist with why, and a stale entry fails.
