# New app checklist

Part of the repo conventions (see `CLAUDE.md` "Read before you touch"). These files are the source of truth; nothing else keeps a copy.

Everything a new app has to touch, so nothing is found missing after merge. Registering an app is not only its registry entry: several pieces outside `src/apps/<id>/` assume every app is wired in. An app is in **beta** while it is access-gated (a `ProtectedRoute appId` and a catalog status that keeps it off the public list). The site installs as one PWA, so an app has no manifest of its own.
- **Register it:** an `APP_REGISTRY` entry (`src/lib/app/app.registry.ts`), the `AppId` union in `src/lib/types/appCatalog.ts`, its route in `src/routes/AppRoutes.tsx` (a `ProtectedRoute appId` for an access-gated app, or the app's own `AppEntryFallback`), logos and banners in `public/`, `cloudflare-worker.js`, and the root `README.md` "Current apps" line.
- **Track usage:** call `useTrackAppUsage('<id>', user?.uid ?? null)` (`@/hooks/useTrackAppUsage`) once from the app's top-level page, next to its `use<App>Sync`, so a member's first visit and later activity are recorded only when they land in that app. Add `functions/src/apps/<id>/findFirstActivityAt.ts` (the oldest timestamp the app holds for a member, or `null`), register it in `FIRST_ACTIVITY_FINDERS` in `functions/src/appUsage/registerAppUsage.ts`, and add its line to the `registerAppUsage` note in `functions/README.md`. Without the finder the callable refuses the app and the tracker logs an error on every visit, so `npm run check:apps` (`scripts/checkAppWiring.ts`, run by `prebuild`, so CI too) fails when a registry app lacks the finder file, its map entry or the hook call. Nothing else is needed for the admin dashboard: it lists every catalog app, and an app's Usage view and the Members view pick the records up.
- **State:** a slice in `src/store/index.ts` that resets on `resetAllState`, its `store/listeners/` and one `use<App>Sync` hook (see "Data and app patterns").
- **Data access:** its `firestore.rules` block under `apps/<id>/…`, `storage.rules` if it stores files, and `firestore.indexes.json` for any composite query. The shared `apps/{appId}/usage` rule already covers usage records.
- **Seed:** `scripts/seeds/<id>.ts` and its document count; the scope in `SeedScope` (`scripts/seeds/types.ts`), the scope checks and branch in `scripts/seed.ts`, and a `seed:<id>` script in `package.json`; an oversized fixture to test at scale (Waypoint's `waypointScale.ts`); `SEEDING.md`; and the app's name in a fixture's `apps` list in `src/lib/dev/fixtureAccounts.ts` so the core seed gives it usage records.
- **Docs and rules:** a short `README.md`, the full `PRODUCT.md`, `UX.md`, `TECHNICAL.md` and `ISSUES.md` under `src/apps/<id>/` (from `plan-app`), and the app's rules file (`.claude/rules/<id>.md`, plus a pointer at `.github/instructions/<id>.instructions.md` as the other apps have), plus a theme stylesheet and `useXTheme()` if it has its own look, which sets `--color-popover`, `--color-popover-foreground`, `--color-tooltip`, `--color-tooltip-foreground` and `--subview-backdrop` in its light and dark blocks (`npm run check:apps` enforces it).
- **Optional wiring, when the app uses it:** `usePresence(…, hereLocation)` for where a member is, and the app id on any `reminders` it schedules.
- **Release:** never edit `SITE_VERSION`; the PR carries one `patch` or `minor` label (see "Quick reference").
- **Later:** an app that leaves the site follows `GRADUATING.md`; keeping the app free of the site's chrome and shared files it doesn't need makes that shorter.
