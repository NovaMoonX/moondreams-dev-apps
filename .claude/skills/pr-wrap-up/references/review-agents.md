# Review agents (technical, product, design)

Spawn all three in parallel with the Agent tool: `model: "sonnet"`, `run_in_background: true`. They are **read-only**: they report findings and the orchestrator fixes. Before spawning the product and design agents, the orchestrator has the emulators, the seeded data (Alex full, Jamie empty, Taylor scale) and a dev server running on a **frozen worktree at the head commit** (fixes made meanwhile must not move what they read; a "before" build on a second port for comparisons). Agents never reset or reseed data and never edit repo files.

## Keeping these sections useful

When the owner says a review agent should have caught something (any wording: "the design agent should've caught this", "this should have been flagged"), the fix is to **that agent's section**, in the same turn as the code fix, and it is an audit of the whole section, not an append:
1. Name the **class** of failure (not the instance) and why the section missed it: no check, a check too vague to act on, a check buried among many, or one that measured the wrong thing.
2. Put it in the group that owns the class and **sharpen that check** (add the measurement that would have caught it); add a group only when none fits.
3. While in the section: merge checks that overlap, replace checks the new one subsumes, delete checks that only restate a `CLAUDE.md` rule (point to the rule instead) or never caught anything, and fix stale wording. `polish-agents.md` and `SKILL.md` point here; they never keep their own copy of a check.
4. Keep each role to about ten groups an agent can run in full, each a test with its measurement and the owner round that taught it. A section that only grows stops being run.
5. Tell the owner in one line what was added, merged, replaced and deleted.

## Technical agent

Review only each PR's own changes: `git diff origin/<base>...origin/<head>` (three dots), no checkouts. Every finding names the **production state** that triggers it ("a week of pending reminders exist and the first run sends all of them"). Groups:
1. **Repo rules** (`CLAUDE.md` Code style, State and Firestore sections: don't restate them here): run the greps `finish-feature-pr` §3 lists (`let `, `for (`, `onSnapshot(`, `fetch(`, `<button`, `persist: true`, `formatDate(` on a date-only field, `crypto.randomUUID`, a template literal in `className`) over the diff and report each hit with file:line; read for what a grep misses (an overlay opened on an overlay, `setState` in an effect body, an unmemoized `useAppSelector` result).
2. **Data contract:** `firestore.rules`, `storage.rules` and indexes against every field and permission the diff touches, including legacy-shaped documents (`resource.data.get(field, default)`) and whether the PR body's verification claims are plausible. **Indexes (the emulator never enforces them):** list every `where`/`orderBy` the diff adds or changes in `src` and `functions/src`; run `npm run check:indexes`, then read `firestore.indexes.json` yourself (the script can't resolve a variable collection path); a missing index, a wrong field order or `queryScope` is a blocker, an index no query uses is a finding. Functions: secrets, cache and budget for third-party calls, `functions/README.md` rows, errors that leak a key or URL.
3. **Writes:** the atomic primitive fits (transaction for derived or cross-document, field-scoped `updateDoc`, `arrayUnion`); a picker never writes and a record created only because another names it is staged in the same batch; **a take-back, Undo or subtraction needs the quantity the source *added* stored with its tag, not recomputed from the source as it is now** (a second add sums those inputs and readers compare by the identity without them; a remainder that may be the person's own is kept and reported; what it can't account for is stated in its result, never explained away); a display option backed by a saved setting flips only after the save succeeds (block the write and watch it).
4. **Derived values, fronts and clocks:** a count or toast reports what the screen draws (rows), not stored items, and says "something else still needs it" only when something does; a local list that mirrors a live one is a `Map` by id, never an appended array. **A derived "which one is in front" (a focused timer, a selected row, an open sheet) gets a table check over every state × event**, including a second alert arriving while one is showing and the order things *finished* in, not started in; a control that is drawn changes the derived value or isn't drawn (round 7: a row that did nothing under a Time's up, a Dismiss that ended a timer nobody had seen). **A ticking display seeds `now` on every show, not only at first mount:** pause the clock right after mounting and read the text (a pill printed the full duration for a tick).
5. **Day-one data:** what is in production when this ships. A fix that unblocks a silent failure (missing index, denied rule, crashed Function) releases its whole backlog: does a sender flush every missed message, a backfill touch every record, a query return thousands? Look for a cutoff and an expiry; check legacy and half-finished records (a `claimedAt` left set, a status that never advanced) and stored settings (a replaced option whose old default was on is ignored, not read as a choice).
6. **Server write meets client listener, and anything that reaches the person outside the page:** trace a field a Function or another user writes through the page's life: the first snapshot after a reload (arrives from an empty store, so "changed from X to Y" sees every record as new), reload, sign-out and sign-in as another user, a second tab or device, what dismissing really changes in Firestore, and the same event arriving by two paths (a push and a toast). A toast, banner, badge or sound driven by a state rather than a watched transition is a finding. For notifications write the matrix (foreground, background, closed then opened, two devices): one delivery per event, no replay; every scheduling call passes a link; an SDK-shown notification is never shown again by hand; a notification for something already past is dropped.
7. **Silent failure and what the environment can't prove:** for every scheduled, background or best-effort path (cron, trigger, swallowed `catch`), how would anyone know it stopped, and is it logged with enough to act on? Name every claim in the PR body that rests only on the emulator, a typecheck or a read-through (indexes, scheduler timing, FCM, a real device, production-sized data) as unverified.
8. **Scale and cost** (`CLAUDE.md` "Performance"): an `Intl` formatter per call, work per row or pair that one pass would do (text derived per row is computed once per change and reused for height estimates too), a memo keyed on something that changes every render, a store that re-renders every subscriber, an uncapped list, a module cache of user data surviving sign-out. **A fixture is evidence only for the data it holds**: when the change adds per-row work on a field the scale fixture lacks, extend the fixture before quoting a number. A function that parses a person's link or page is benchmarked against a 1.5 MB body of 100,000 repeated tags and of 780 tags padded with long whitespace, and every collection it builds is capped before any quadratic step.
9. **Layers, back and offline:** every new drawer, sheet or swap-in view closes on the back gesture one layer at a time (a history entry, or it says why not) and Escape steps out of a swapped-in view; focus moves in on open and back to the opener on close, **and an event never moves it behind a dialog:** with a confirm open, drive the event that moves focus (a timer finishing, a snapshot arriving) and print `document.activeElement` and the dialog's text (round 7: focus jumped to a button under "Stop timers and leave?"); a write made where signal drops (ticks, adds, eating, planning) doesn't hold its form for the server, or the PR says why.
10. **Gaps and honesty:** seeds, docs, `SITE_VERSION`, unmet issue checkboxes, a component that exists but is unreachable, **doors and the sitemap** (`UX.md` and `JOURNEYS.md` §4.1 updated, a journey named per new door), a merge or dedupe that drops provenance (sources, tags) from the survivor, a hunk that only reflows untouched files (revert it), and words that promise more than the code does: a comment naming a cap the rules don't enforce, a check title that claims more than its assertion proves (one that names an order or a rule, "first to finish", needs input data that carries it, or the title is the finding), a React key two siblings can share (built from a label, or one id reused by siblings built in different variables), a `CLAUDE.md` or rules-file rule the change now contradicts (amend it in the same PR).
Also name any feature-specific risk the brief lists (money math, time zones, transitions, a backlog the change releases, a new query and its index, transactions, memoization keyed on `now`, concurrency).
