# Gap lenses

`gap-hunter` walks every feature of a plan through each lens below. Each lens names the owner question that earned it, so the list grows from real misses. Add or sharpen a lens whenever the owner asks a "what about…" the hunt should have raised, or the hunt reports one under **Lenses missing** that the lead agrees with; merge lenses that overlap and drop one that has found nothing in three plans (`docs/conventions/pipeline.md` "The pipeline improves itself").

1. **Timing and change of mind.** Wanted sooner, later, cancelled, edited midway, undone, done twice, done outside the app. (owner, Helm growth: "what if I want the overnight research right now?")
2. **Transitions between states and modes.** Offline and online, private and not, spoken and typed, a permission on, off or refused, a linked thing deleted, done or abandoned.
3. **Who decides.** For every rule, code (static, checked) or the model (prompt); a model decision needs a code check. (owner, Helm growth: "is that a fixed rule, or does it depend on the agent?")
4. **What the person sees of a mechanism.** The result, not the machinery; a result that arrives with no signal; a silent failure. (owner, Helm growth: "is it more important that the user gets the result?")
5. **How far a rule reaches.** A rule written for one case that should cover all. (owner, Helm growth: private beyond health)
6. **When a permission or ability is asked.** Never up front; offered where a request needs it. (owner, Helm growth: location)
7. **Scattered themes.** A theme the owner would ask about ("what does the plan say about X?") whose answer is spread thin or missing. (owner, Helm growth: location)
8. **Failure and limits.** A provider down, an allowance spent mid-task, a wrong model answer, a job that never comes back.
9. **Other people.** Shared things, another person's data, someone named who isn't a user.
10. **Growth over time.** A year of data, fifty of a thing, new kinds of record, what goes stale.
11. **Collisions.** Two features acting on the same thing at once.
12. **One rule, one wording.** Every number or behaviour stated in more than one doc (timings, caps, what happens at a limit) is lined up side by side; any difference is a gap. (gap hunt 1, Helm growth: three research timings)
13. **Every promise has a way to keep it and a line for when it fails.** "I'll tell you when it's in", "back by morning", "Noted": what delivers it, what the person sees if it doesn't, and whether it stays true in every state (learning off, offline, over a limit). (gap hunt 1)
14. **A no-AI path for safety actions.** With the model down, the person offline or over a limit, which actions still work in code alone, health and care first. (gap hunt 1: a spoken pill tick)
15. **Late data after a decision.** A backfill, offline sync or edit that lands after a week, batch or stage was judged: is it judged again? (gap hunt 1)
16. **Derived things take their sources' class.** Every summary, pattern, moment, timeline entry and Activity line follows its sources' privacy, delete cascade and retention. (gap hunt 1)
17. **Where it lands and where it's found.** For every kind of thing a person can say, which record it becomes, the reply that tells them, and every place they can find it again (a page, a list, Search, asking); and where two kinds sit close (learn about something vs a goal to practise), how the boundary is told apart and asked when unclear. (owner, Helm growth: "if I say one day I want to learn how engines work, where does that get filed, and where can I see it?")
18. **A no has reasons.** Every decline or Not now: which reasons it can carry (timing, lost interest, changed mind), how a tap is told apart from words, what each changes, and what repeated declines do. (owner, Helm growth: "not now could be lack of interest, a changed mind, or just the time")
19. **Related things meet.** When something new is close to something kept or saved, does the system connect them, who decides (model or code), and what caps it so it never nags. (owner, Helm growth: electric cars with "how engines work" saved)
20. **How it ends.** Every conversation, flow and listening state: how the person ends it in their own words ("never mind", "forget it", "that's all"), what is dropped and what stays, how fast it closes (on the device, no round trip), what it says or doesn't, and how an ending phrase is told apart from a request that uses the same words. (owner, Helm growth: "better detection for when a conversation is coming to an end")
21. **As good as the tool they already know.** For each thing the person sets up (a repeat, a reminder, a share), name the familiar tool that does it best (Google Calendar's repeat, a phone's alarm) and check the plan can say everything that tool can, as easily, with the common choices one tap away. (owner, Helm growth: scheduled actions "similar to how Google Calendar does it")
22. **What it already knows helps it hear.** Wherever the person speaks or types a name, does the system use the names it already holds (people, places, pets, projects) to hear and read it right, what leaves the device as a hint, and how a correction teaches it. (owner, Helm growth: odd names misheard)
23. **Every worked-out value names its inputs.** For anything the plan derives (an order, an age, a total, a "nearby"), list each input, where it is stored, who or what can write it, and what happens when one is missing (ask the answer itself, never demand the input). (owner, Helm growth: "wouldn't that mean the system needs to know how old the current user is")
